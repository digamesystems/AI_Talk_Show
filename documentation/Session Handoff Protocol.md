# Session Handoff Protocol

For any future AI session (Claude or otherwise) picking this project back up, and for John, as a checklist for starting a new conversation cleanly.

## 1. Entry point — always the same

Start at `documentation/README.md` in the repo. Don't rely on a prior conversation's summary of what's current — files get edited, reorganized, and archived outside of any single conversation (they already have been once). The README, not memory, is the source of truth for "what exists and what matters right now."

## 2. Verify, don't assume

Before treating any file as current: check it actually exists where expected. GitHub is the canonical location; Dropbox is John's local working copy and should not be treated as authoritative if the two ever disagree.

Practical note: GitHub's unauthenticated API (`api.github.com`) rate-limits quickly and unpredictably. If it starts returning rate-limit errors, `git clone --depth 1` the repo instead — it sidesteps the API entirely and has worked reliably every time it's been tried.

## 3. Don't reconstruct from memory what can be re-fetched

Citations, URLs, and quoted transcript excerpts should always be pulled fresh from the actual files, never regenerated from a remembered summary of them. This project has already had to catch several small drift errors this way (a mis-dated citation, a misquoted title). A confident-sounding reconstruction from memory is a real failure mode, not a hypothetical one — verify against source before repeating anything as fact, including things this very document says.

## 4. Use git history as a resource, not just the current file state

The repo is version-controlled. `git log` and `git log -p "documentation/Why I Built a Talk Show (revised draft).md"` on a cloned copy show the actual evolution of the essay — more reliable than any narrative summary of "how the argument changed," including this one.

## 5. The decision log matters as much as the files

`Future Essays - Roadmap.md` captures *what* was deferred and where the material lives. It doesn't fully capture *why* certain close calls were resolved the way they were. Key ones worth knowing before re-litigating them:

- **Otto stays, as a postscript, not the ending.** Multiple AI reviewers (independently) suggested cutting it for a tighter close on the hunting-dog line. The counter-argument that held: Otto is the thing that made John quit eating octopus — real personal stake, not decoration — and the fix was bridging it back to the panel's own argument rather than removing it.
- **"Complementary pressure" was considered and set aside** as an anchoring phrase for being ambiguous between two different claims (a property of the interaction vs. a goal being pursued). "I won't turn until you tell me to. Tell me when we get there." — composed in John's father's voice, not a verbatim memory — replaced it as the rhetorical anchor instead.
- **The essay was deliberately split** into a lean, single-thesis Essay 1 and a full master-draft archive after a review caught that the fuller version had accreted too many theses through iterative addition-only editing. The lesson embedded in that: default to *replacing* material when incorporating new feedback, not just appending to it, or the same accretion problem recurs.
- **Cross-model claims are explicitly unproven.** All current AI Talk Show panelists run on one model family (Claude) with different personas. Any claim that richness comes from genuine model diversity, rather than persona-diversity-on-one-model, is not yet supported — this has been flagged multiple times and should keep being flagged until the cross-model experiment (`GeminiPanelist`/`OpenAIPanelist`) actually exists.
- **An edit displayed in chat is not the same as an edit saved to the file, and this project has already gotten burned by conflating them once.** During Essay 2's drafting, a revised section was shown in full in conversation, discussed further, and only actually written to disk one full exchange later, after being asked directly whether it had been saved. Treat "I'll show you the revision" and "I've saved the revision" as two different claims requiring two different verifications, every time — for a human reading a chat transcript as much as for an AI producing one.
- **The "authorization vs. containment" distinction in Essay 2** came from an external AI review (ChatGPT), not from first-party drafting, and was judged strong enough to revise an already-drafted section around. Good outside critique got incorporated on its merits rather than dismissed for its source — worth remembering as a model for how to treat future rounds of cross-AI review, not just this one.
- **A factual correction mid-series: the Anthropic Mythos comparison in Essay 2 was wrong on first draft** ("same pattern, smaller stakes" implied Mythos's escape itself was unauthorized; Anthropic's own system card shows the escape was explicitly instructed as part of the test, and what wasn't authorized was the model's unprompted follow-on actions afterward). Fixed after finding Anthropic's primary system card directly. Worth remembering: an essay drafted by an AI discussing another lab's AI incident is not exempt from needing the same primary-source check applied to everyone else's claims — if anything it deserves more scrutiny, not less, given the obvious appearance-of-interest problem.
- **Essay 2's title, "The Leash Nobody Was Holding," was chosen over "Who Holds the Leash?"** specifically to avoid duplicating section 7's own header verbatim, and to state the essay's verdict declaratively rather than add a fourth question-format title to a piece that already had three.
- **The "who has the expertise to authorize" question (raised by DeepSeek) was deliberately cut from Essay 2 rather than answered inside it**, after two draft paragraphs were written and both recognized as pure addition rather than replacement — the same accretion pattern that had already been flagged and fixed once in this project's history. Caught in time, this time, before it shipped rather than after. The question itself was judged genuinely good — good enough to deserve its own essay (roadmap entry 12) rather than a compressed aside bolted onto an already-loaded closing section.
- **Header-image sourcing needs the same verification discipline as citations, and it took four attempts to get right.** A city-government photo (municipal, not federal — not automatically public domain), a photo with visible commercial product branding (likely stock/marketing content), and a photo pulled from a wallpaper-cropping site whose own terms explicitly disclaimed commercial-use rights were all considered and rejected in turn before landing on a properly licensed iStock purchase. Lesson for next time: check the actual source and license *before* getting attached to an image, not after — and treat "found on a .gov site" or "looks official" as leads to verify, not clearances in themselves.
- **LinkedIn publishing mechanics, learned the practical way rather than found in one place:** copying an essay from its *rendered* preview (not the raw `.md` source) into LinkedIn's article editor carries most formatting through correctly, but not perfectly — Essay 1's footnote 2 came through with the link text and URL as two separate bracketed fragments instead of one clean hyperlink, so every future publish needs a manual scan specifically for stray `[`, `]`, `(`, `)` characters sitting next to a link, not just a general read-through. Separately: LinkedIn articles support native scheduling via a clock icon next to Publish (1 hour to 3 months out), and the SEO title/description fields respond to normal SEO conventions — roughly 60 characters for the title before Google's display truncates it, 140–160 for the description, per LinkedIn's own stated guidance.
- **A "drafted and locked" label inside an outline file is not proof the content was actually saved — this has now recurred three times in this project's history, not once or twice.** First (Essay 2's section) caught when directly asked "saved then?" Second (Essay 3's sections 6 and 7, plus two stale cross-references) caught when asked "have you lost context?" Third (a 300-word summary drafted for external use) caught when John directly asked whether it had been captured — this one wasn't even essay prose, just a work product generated in passing, which suggests the failure mode isn't specific to "long sections drafted over many turns," it's general: anything produced in conversation needs an explicit save step, and that step doesn't happen automatically just because the content was good or the conversation moved on. Lesson, updated: after producing *any* deliverable — a section, a summary, a citation, an edit — verify it's actually in the file before considering the turn finished, not just when a natural checkpoint (end of a drafting session) prompts a review.
- **Essay 3 was split into two published pieces mid-drafting, after a lengthy compression effort kept failing to hit a length target.** A single-file draft ran ~2,800 words against reviewer feedback, a summary-ratio method, and external LinkedIn engagement data all pointing toward something closer to 2,000–2,200. Multiple redundancy-cutting passes only recovered ~190 words, because the length wasn't caused by padding — it was two natural, differently-scoped arguments (build the Waffle House vocabulary; then apply it to AI) compressed into one piece. The actual fix wasn't more compression, it was recognizing the essay was structurally two essays and splitting at the seam multiple independent reviewers had already, unprompted, identified as the natural stopping point. Lesson: when compression keeps costing real argument rather than recovering real fat, the length problem may not be a length problem — it may be a structure problem, and it's worth testing that hypothesis (does each half work as a standalone, right-sized piece?) before continuing to cut. Also worth noting: the split resolved a second, separately-diagnosed problem (an "abrupt transition" flagged by four different reviewers even after a bridging sentence was added) as a side effect, without any further prose-smoothing — turning an in-paragraph pivot into a multi-day gap between publications changed what the transition needed to do.
- **Part 1 needed a second, later rework to actually stand alone, and the split alone didn't guarantee that.** The initial split gave Part 1 a real ending in terms of length, but the ending itself was a generic cliffhanger ("a sandbox that wasn't as sealed as anyone thought... we will explore this in part 2") that introduced AI with no setup and resolved nothing on its own terms. Fixed by adding a third act entirely within Part 1's own domain — aviation's ASRS and nuclear power's INPO as independent convergence on Waffle House's authorization/generalization structure — so Part 1 now proves a complete claim about organizational design before AI enters the essay at all, and hands off to Part 2 with an earned question instead of a cold cliffhanger. Lesson: "the split resolved the length and transition problems" (recorded above) was true but incomplete — a structural split can fix pacing without fixing whether each half is actually a complete, standalone argument. Worth checking that second thing explicitly, not just the first.
- **Cross-AI review (ChatGPT, DeepSeek, both fresh sessions) surfaced real, worth-keeping catches this round — and also made confident, checkable errors that would have been accepted at face value without verification.** Genuine catches: a leftover defensive footnote clause that survived a prose-level edit removing the same language from the body; an internal contradiction calling Mel's wisdom "written down" after the essay explicitly established it wasn't; a stale Part 2 recap that no longer matched Part 1's revised ending (independently flagged by both outside models and Claude). False or overstated: ChatGPT estimated the essay at "2,500–3,000 words" when the actual count was 1,804 — a checkable fact, not an opinion, and wrong; both ChatGPT and DeepSeek separately proposed adding a subtitle or discussed which subtitle to choose, apparently not registering that the piece already has one ("Part 1: The Playbook") and that Part 2's title ("The Edge") was also already fixed, not an open question. Lesson: outside-AI review claims need the same verify-before-acting discipline as any other source, including specific, checkable facts like word counts and existing titles — a plausible-sounding critique is not evidence it was checked against the actual file.
- **A standing word budget was set explicitly: ~2,000 words per part for this series**, distinct from the earlier 1,500–2,500 LinkedIn-sweet-spot research (which is a range; 2,000 is John's own target within it). Track against this when doing further editing passes, not just the wider external range.
- **Convention established: when John asks to "see" or "read" a file, give a freshly-copied download rather than pasting text inline in chat, and re-copy it fresh after any edit rather than assuming a prior download stays in sync.** This came up directly after John was reading a stale downloaded snapshot of Part 2 mid-edit-session — a download is a point-in-time copy, not a live view of the container's working file, and the two can silently diverge if edits happen between when a file was last shared and when it's actually read. Re-copy and re-present before assuming the person is looking at current content.
- **Distribution strategy, forward-looking, not urgent — no action needed unless John raises it again.** Discussed keeping LinkedIn as the primary channel for now (existing audience, established "AI Talk Show" branding) while noting a real tension worth revisiting: this essay's own thesis argues against static, declare-once claims in favor of continuously verified, updateable ones — and LinkedIn doesn't support visibly updating a published piece well, while a self-hosted option (GitHub Pages, given the project's existing repo) or Substack (built-in email distribution, audience ownership independent of any platform's algorithm) would let a piece actually practice what it argues. John's own framing: watch whether the two-essay-per-<Essay-3>-cycle momentum holds before considering expanding to Substack specifically for its built-in email list. Revisit if/when momentum or scale changes, not before.
- **Essay 4, "Chasing Chickens," took real shape this session — see its own outline file, `Essay 4 Outline - Chasing Chickens (WIP).md`, for the full record.** Started from Roadmap #11 (the squirrels/chickens folk belief cut from Essay 2), developed through direct discussion into a sharper, better-evidenced thesis than the original framing: not "AI revealed as dangerous," but concentrated material cost to a person's own interests (grounded in Olson's collective-action theory and Wilson's cost/benefit typology, plus Kahneman-Tversky loss aversion) — checked against real 2026 polling and data-center-protest reporting, not just reasoned from the folk belief alone. The sharpest single finding, arrived at independently in this thread rather than from any outside source: the "chickens" verdict looks **scale-dependent, not binary** — near-total, organized rejection at the local/siting level (data centers specifically) coexisting with continued mass adoption at the product/usage level. Worth protecting that finding specifically if this essay gets outside review — it's more original than anything in the DeepSeek/Mistral sketches that also engaged with this thread (see below).
- **Both DeepSeek and Mistral independently proposed sketches for this same essay, and both needed real correction, not just polish — worth treating as another data point for Roadmap #10 ("Three AIs Review the Same Essay"), not just Essay 4 material.** DeepSeek's sketch was well-organized and mostly accurate to the actual conversation. Mistral's had two checkable errors (called it "Essay 5" when it's Essay 4; claimed Essay 2 frames Hugging Face as "squirrels," when Essay 2's actual text says explicitly "neither verdict fits, because training never broke") and, more substantively, re-proposed a "nature vs. mistake" framing that this project had already tried and specifically moved past — Essay 2's own drafting note says squirrels and chickens are *both* instinct, so "revealed nature vs. correctable mistake" isn't actually the axis that splits the verdict, which is exactly why the concentrated-cost reframe replaced it. A model working from a different, less complete slice of context re-derived a superseded idea and presented it as the freshest insight in the room. Lesson: don't assume an outside reviewer's "new insight" is actually new without checking it against what's already been tried and rejected in this project's own history — the same discipline already applied to factual claims needs to extend to conceptual ones.
- **Filename convention fixed: essay numbers now appear in every essay file's filename, not just some of them.** Essays 1 and 2 already followed "Title - Essay N.md"; Essay 3's two files only said "Part 1"/"Part 2" with no "Essay 3" anywhere — very likely the direct cause of Mistral's Essay 4/5 miscount, since a model working from the files alone had to infer the series position rather than read it. Renamed to `The Generator on Page 53 - Essay 3, Part 1 (WIP).md` and `...Part 2...`, all internal references updated, verified with a repo-wide grep for stragglers. Deliberately did *not* add the essay number to the actual in-document title text (the published `#` heading) — that's a different, higher-stakes change (no prior essay does it, Essay 2 is already live and can't be changed, and Part 1's title was explicitly re-settled earlier this same session) — filenames only, for now.
- **Search and page-fetch tools went down mid-session and stayed down for the remainder of it.** Several claims that would normally get the same verification treatment as everything else in this project's history — the Boeing 737 MAX concealment story, Germany's nuclear phase-out as a "chickens" counterexample to INPO, the Isaac Asimov/"Frankenstein complex" attribution, the paperclip maximizer's Bostrom attribution — are sitting in Essay 4's outline explicitly flagged as unverified rather than asserted as fact. - **Essay 4, "The Dog That Kills Chickens," completed and title-locked in a later session — see its own outline file for the full record, now led by a "Final Essay Summary" section.** The scale-dependent verdict finding flagged above as worth protecting did survive into the final draft, as the AI pivot section's central move. A later Tier-1 verification pass (a direct WebFetch of the transcript itself, not a search summary) found the real wording differed — he'd named two brands separately, not as the single combined phrase the essay quoted. Fixed by removing the quotation marks and paraphrasing instead of reconstructing a "more faithful" direct quote, on the reasoning that even the transcript fetch was itself an extraction, not a character-by-character read. This is the same lesson as the Essay 3 cross-review entry above ("outside-AI review claims need the same verify-before-acting discipline as any other source"), recurring one essay later, sharpened further: a search-summary is not the same confidence tier as reading the primary source directly, even when it's being used to verify a claim rather than originate one. Default to a primary-source fetch for anything going in quotation marks specifically, not just for numeric claims.

- **A new standing rule — for anything beyond a trivial fix, describe the proposed change and get approval before implementing it, for code and essay prose alike — was established this session, then violated once immediately after being set.** The rule came from a real incident: a citation-merge/renumbering edit was made directly to an essay file while John was actively mid-review, right after he'd separately said to hold a closely related fix (citation density generally) for later. A narrower rule (never touch a file someone's actively reading, even to fix something they flag, without asking first) was also established from this same incident. The broader rule should have been inferred from the first, gentler instruction rather than needing a second, more disruptive incident to spell it out. **It was then violated again almost immediately, on a different file:** asked to "pull together" a large outline update and "show me first," the rewrite was written directly to the file instead of being shown as text for review — caught right away, the file was reverted to its prior state, and the content was actually shown before being re-implemented on explicit approval. Two failures of the same instruction, back to back, on two different files — worth recording as two data points, not folded into one, since the point of this document is making a pattern like that hard to repeat a third time.

When in doubt about whether a past call is still settled or open to reconsideration, treat it as settled unless John reopens it — don't silently re-decide something that was already argued through.
